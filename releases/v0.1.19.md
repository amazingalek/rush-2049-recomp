San Francisco Rush 2049: Recompiled v0.1.19: controller bindings stay set from one session to the next.

> **Made with AI.** Almost all of the code was written by AI agents (Claude), directed and play-tested by a person.

You need your own ROM of the US release (`.z64`, SHA-1 `3f99351d7bb61656614bdb2aa1a90cfe55d1922c`); the launcher finds it by itself in a usual place (the game's folder, Downloads, Desktop, Documents and one level of subfolders), otherwise pick it with **Load ROM**.

**Windows:** unzip `Rush2049Recompiled-v0.1.19-windows-x64.zip` and run `Rush2049Recompiled.exe` from that folder. **Linux (x86-64):** extract `Rush2049Recompiled-v0.1.19-linux-x64.tar.gz` and run `Rush2049Recompiled` in that folder (glibc 2.35 or newer, a Vulkan driver, GTK 3 and FreeType). Settings and saves carry over from earlier versions.

**Fixed:** with **Controllers** at Per Player, bindings set on the Controls tab could be back to other values the next time the game started. Each controller's bindings are saved with the controller, but the game never matched a saved controller to one that is connected, and found its bindings only by a name that includes the controller's serial. For a Bluetooth controller the serial can come out differently from one session to the next, and then the controller got new bindings copied from the One Player ones. It now gets its own saved bindings back. If yours were reset before, set them once more. The log (`rush2049.log`) also says for each controller whether the game knew it already.

The [README](https://github.com/n64hub/rush-2049-recomp#readme) has the controls, every setting, and how to build it yourself.
